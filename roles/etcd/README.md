# `etcd` role

The `etcd` role configures and starts [etcd](https://etcd.io/), the key-value store of the Kubernetes cluster, on the
control-plane nodes or on dedicated etcd nodes. furyctl runs it during the installation of a cluster and again during an
upgrade, when the role also stages the new etcd version and renews the etcd certificates; see the
[installer README](../../README.md) for how furyctl uses the roles. Besides its `main` entry point, the role has the entry
points `pre_reboot.yml` and `post_reboot.yml`, which an upgrade runs before and after the reboot of a dedicated etcd node.

## Requirements

- The etcd system extension from the [installer-immutable-sysext](https://github.com/sighupio/installer-immutable-sysext)
  repository is installed on the node: the etcd binaries, user and service.
- The kubernetes system extension is installed on the node: the role generates the etcd certificates with its `kubeadm`.
- The node configuration generated by Butane created the placeholder `/etc/etcd/etcd.env` and the directory
  `/var/lib/etcd`.
- `furyctl create pki` generated the etcd certificate authority in `pki/etcd/`, the directory that
  [`etcd_pki_local_dir`](#variable-etcd_pki_local_dir) points to.
- Every node has a DNS record that the other nodes resolve: etcd forms its cluster with the host names of the nodes, as the
  [Immutable installation guide](../../docs/IMMUTABLE_INSTALL.md#prerequisites) explains.

## Entry point: `main`

Configure and start the etcd member of the node.

Copies the etcd certificate authority created by `furyctl create pki` to the node, generates the server, peer and client certificates of the member with `kubeadm`, writes the etcd environment file and an `etcdctl` profile, and starts etcd, restarting it when its environment file changed. When the variable `tls_cipher_suites` is set, the environment file also restricts etcd to those TLS cipher suites (`ETCD_CIPHER_SUITES`). When etcd does not run on the control-plane nodes, the role copies the etcd CA certificate and the etcd client certificate and key of the API server to the nodes of [`etcd_ansible_group_name`](#variable-etcd_ansible_group_name) after it generates them.

During an upgrade, the role stages the new etcd system extension, renews the etcd certificates after a backup, and does not restart etcd for a changed environment file.

### `etcd_config_dir`<a id="variable-etcd_config_dir"></a>

Directory where the role writes the etcd environment file `etcd.env` and the `kubeadm` configuration `kubeadm-etcd.yml` that generates the etcd certificates.

The renewal of the certificates during an upgrade always reads `/etc/etcd/kubeadm-etcd.yml`, whatever the value of this variable is.

### `etcd_certs_dir`<a id="variable-etcd_certs_dir"></a>

Directory of the TLS certificates and keys of etcd. The etcd environment file and the `etcdctl` profile point to the files in it.

Setting the owner and permissions of newly generated certificates, and renewing the certificates during an upgrade, always use `/etc/etcd/pki`, whatever the value of this variable is.

### `etcd_initial_cluster_state`<a id="variable-etcd_initial_cluster_state"></a>

Initial state of the etcd cluster (`ETCD_INITIAL_CLUSTER_STATE`): `new` to bootstrap a new cluster, `existing` for a member that joins a running cluster.

Choices: `new`, `existing`.

### `etcd_certs`<a id="variable-etcd_certs"></a>

Files, relative to [`etcd_certs_dir`](#variable-etcd_certs_dir), that the role copies to the nodes of [`etcd_ansible_group_name`](#variable-etcd_ansible_group_name) when etcd does not run on the control-plane nodes.

Default:

```json
[
  "etcd/ca.crt",
  "apiserver-etcd-client.crt",
  "apiserver-etcd-client.key"
]
```

## Entry point: `pre_reboot.yml`

Check the etcd cluster and back up the etcd member before the node reboots.

Used during an upgrade, before a dedicated etcd node reboots for an operating system update. Fails unless every member of the etcd cluster is healthy, then saves a snapshot of the etcd database of the member to `$HOME/etcd-backup` on the node. A failed snapshot fails the run, so the node never reboots without a backup.

This entry point takes no variables.

## Entry point: `post_reboot.yml`

Wait for the etcd cluster to be healthy again after the node rebooted.

Used during an upgrade, after a dedicated etcd node rebooted. Checks the health of the etcd cluster and, until every member is healthy, checks it again every 5 seconds, up to 30 more times; it fails when the cluster is still not healthy. It then moves the snapshots saved by the `pre_reboot.yml` entry point from `$HOME/etcd-backup` to `/tmp` on the node.

This entry point takes no variables.
